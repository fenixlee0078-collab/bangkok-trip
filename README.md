# bangkok-trip

曼谷 + 清迈 6 天 5 夜行程站（纯静态，托管在 GitHub Pages）。

打开：https://fenixlee0078-collab.github.io/bangkok-trip/

## 这东西是什么

一个可以随时改的行程网页。手机上打开就能编辑、加地点、记费用，改动存进你自己的私有仓库。

跟"服务端版"的区别：

| | 服务端版（本地跑 node） | 这个静态版 |
|---|---|---|
| 地点搜索 | 服务端调谷歌（本地走 Clash） | **浏览器直接调谷歌** |
| 数据存放 | 服务端内存 + data.json | **GitHub 私有仓库** |
| 是否需要开电脑 | 需要 | **不需要** |
| 搜索能用吗 | 看那台机器能不能到谷歌 | 看**你手机**能不能到谷歌 |

## 三个 Key / 令牌，别搞混

| 名称 | 干什么用 | 存哪 | 能不能公开 |
|---|---|---|---|
| 谷歌 Key（浏览器专用） | 搜索地点 | `site-config.js` 或页面里现场填 | ✅ 可以公开（已按网站来源限制） |
| GitHub 令牌（数据） | 读写私有仓库里的行程 | **只存手机浏览器 localStorage** | ❌ 绝对不能提交进仓库 |
| 数据仓库 | 存 `data.json` | `site-config.js` | ✅ 可以公开 |

⚠ `site-config.js` 里**永远不要写 GitHub 令牌**。这个仓库是公开的。

## 怎么配置

1. 手机打开站点
2. 拉到页脚，点 **☁️ 云端同步**
3. 填数据仓库（如 `fenixlee0078-collab/bangkok-trip-data`）
4. 填 GitHub 令牌（只授权那一个私有仓库、Contents 读写的 fine-grained token）
5. 填谷歌 Key（如果 `site-config.js` 里已经填好就不用管）
6. 点「保存并测试连接」

配置只存在这台设备的浏览器里，换设备要重新填一次。

## 文件

```
index.html         页面骨架（静态版：socket.io 换成 static-bridge.js）
app.js             全部前端逻辑（与服务端版完全一致，未做改动）
static-bridge.js   静态版桥接层：把服务端的 io() 和 /api/* 在浏览器里补齐
site-config.js     站点配置（地图源、城市、搜索中心、数据仓库、谷歌 Key）
data.json          行程数据的初始快照（云端没有数据文件时用它起步）
style.css / theme.css
```

`app.js` 之所以一行都不用改，是因为 `static-bridge.js` 在它之前加载，
把 `window.io` 和 `window.fetch` 接管了 —— 前端以为自己在跟原来的后端说话。

## 已知限制

- **搜索需要能访问谷歌的网络**。国内不挂梯子时搜索会失败，但行程的查看和编辑照常。
- 数据同步是**最后一次写入胜出**。两台设备同时改，晚保存的那台会覆盖早的。
- 没有实时同步（原版的"谁在线 / 边改边看"没了），改动靠保存后重新打开刷新。
